# Atomic App Mode transitions and deferred reopen

Chowser supports two live presentation modes: App Mode has a Dock icon and native application menus, while Menu Bar Mode has a status item and no Dock icon. Changing only `NSApplication`'s activation policy left those three pieces of state out of sync: the persisted preference, activation policy, and status-item lifecycle. In particular, switching App → Menu Bar hid the Dock icon without creating a status item, leaving users unable to reach the app.

Mode changes are now one ordered operation. App → Menu Bar creates and configures the status item before switching to accessory activation and persisting the preference. Menu Bar → App switches to regular activation before removing the status item and persisting the preference. A failed transition first rolls back to App Mode. If macOS also rejects that rollback, Chowser keeps the newly created status item as a recovery entry point instead of removing every way back into the app. Settings, onboarding, and the local API use the same transition entry point; API requests are fully validated before mode side effects run.

App Mode also needs normal Dock-reopen behavior. Opening Settings synchronously from `applicationShouldHandleReopen` races URL delivery because AppKit may call reopen immediately before `application(_:open:)`. Chowser therefore schedules a short deferred reopen, and URL handling cancels it before routing. Privacy-safe lifecycle diagnostics record session boundaries, mode transitions, status-item changes, Settings presentation, and failures without recording URLs, hosts, source applications, usernames, clipboard data, or local paths. Exported reports use only this typed channel; the UI separately labels general logs as raw because existing operational messages can contain user-authored names or error details.
