Verdict: useful later, but it should not block the routing and rewrite work.

Evaluation

Keep

Fallback browser. Tiny settings surface, high value for users who mostly route to one browser.

Keep

Typed rewrites. Fixes messy links without importing a scripting runtime.

Keep

Multiple source apps. Natural extension of Chowser's existing source-app rule support.

Maybe

Picker URL editing. Nice and small, but likely lower usage than fallback and rewrites.

Maybe

Open-with extension. Useful once the core link pipeline is clearly better than browser-native opening.

Maybe

Profile polish. Worth doing after core routing: markers, hotkeys, and Safari profile feasibility.

Maybe

Desktop and mail targets. Useful later, but they widen Chowser beyond browser routing.

Skip

JavaScript config. Powerful, but too much validation, sandboxing, and support cost for Chowser.

Suggested order

1
Fallback browser
Small model change, obvious UI.
2
Source app chips
Extends current rules without a new page.
3
Typed rewrites
New page, new data model, worth designing carefully.
